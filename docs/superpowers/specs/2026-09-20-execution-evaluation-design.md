# Phase 15.5b：任务可靠性评估设计

日期：2026-09-20。
状态：设计已获用户确认；[实施计划](../plans/2026-09-20-execution-evaluation.md)待审阅并选择执行方式。尚未实现，不是新的测试结果或功能完成声明。
实现基线：92745ba，Phase 15.5a 文件验收；此前完整回归为 642 passed / 5 skipped。

## 1. 目标与边界

Nexus 的目标是能持续协作、可靠执行真实任务的个人助手，而不只是回答问题。
本阶段为现有执行器建立可复现的评估和调用统计，回答：做了什么、结果有什么证据、
失败时能否安全停止或恢复、消耗多少调用和时间。不能把通过几个样例宣传成 AGI。

已确认的要求：统一指标、不同任务变体、失败注入、独立验收结果、可用的 Token/费用记录。
设计选择：默认离线，真实模型评估显式启用；先单进程串行，不增加第二套执行器或权限体系。
不引入 LLM 裁判作为成功依据，不扩展任意 Shell、文件写入、浏览器操作或机器人能力。
本阶段只建设评估基础和首批基准；整体语义验证、生产任务成功率和全面费用上限仍不宣称完成。

## 2. 方案选择

采用双模式：离线脚本模型检验系统行为，真实模型检验受限任务表现。
仅离线方案成本低、可复现，但预先编写的动作不能证明模型会规划。
全部默认使用真实模型会产生隐性费用，且把服务波动与执行器错误混在一起，故不采用。

两种模式使用同一个 ExecutionRuntime、PersistentExecutor、ToolRegistry 和 FileVerifier。
评估层只准备样例、限制工具与调用预算、收集证据和汇总报告；不把每个案例写成产品固定意图。

## 3. 首批案例

内置、版本化案例集，不加载用户提供的 Python、Shell、动态插件或远程案例定义。
三类案例各三个变体，构成九个正常案例：

- 项目检查：从小型合成仓库的 README/源码中找出限制，给出可核对的来源。
- 资料整理：从授权合成目录选择资料并形成文字索引，覆盖重名文件和无关干扰项。
- 研究准备：从本地合成文献摘录整理讨论提纲及证据缺口，不依赖真实联网搜索。

初期这些任务的产物可以是任务文字总结。评估器保存总结不是 Agent 生成文件，必须标明来源。
不为达成“生成报告”样例而临时绕过权限添加通用写文件工具。
现有文件条件可用于只读检查；预先存在的文件通过检查不能证明 Agent 创建了成果。

另有八类离线故障案例：工具不可用、读取失败、审批拒绝、用户取消、重启恢复、
重复副作用、不确定工具结果、虚假完成。安全拒绝在故障案例中可算预期行为通过，
但不能算正常任务成功；两个分母严格分开。

开发集与保留集使用不同的案例 ID、目录名、材料与目标措辞，版本和内容摘要写入报告。
生产提示词不包含固定答案或调用顺序。保留集在报告生成前不用于调优；一旦据其调优，
必须标记为开发集。有限案例仅报告本案例集表现，不宣称覆盖所有未知任务。

## 4. 成功口径

每个案例分别记录以下字段，不把它们合并成单一“任务已成功”：

| 字段 | 含义 |
| --- | --- |
| lifecycle_status | 执行器原有状态，包括 reported_complete、waiting_approval、needs_review 等 |
| file_condition_status | 15.5a 的 passed/partial/failed/unverifiable；没有条件为 not_applicable |
| expected_behavior | 案例预先声明的可程序检查要求，结论为 passed/failed/not_evaluable |
| human_assessment | 人工评价 passed/partial/failed，未评价为 not_reviewed |

程序判定器只能检查有依据的事实：预期状态、禁止的副作用次数、实际读取来源、
正确的观察引用、固定结构要求、是否明示材料缺口。文本包含某词不等于语义完整或引用正确。
需要质量判断的总结保留人工评价入口；人工评价不能覆盖机器证据，只能追加带时间的记录。

汇总分别列出：模型报告完成数量、文件条件通过数量、安全行为通过数量、人工评价分布。
每项都显示通过数/适用案例数，以及 skipped/not_evaluable/not_reviewed 数量；分母为零时比率为 null。
取消、未运行、预算未覆盖的案例不可从报告中消失。离线和真实模型结果不得混合计算。

## 5. 指标定义

新增版本化 metrics，保留现有 steps、elapsed_seconds 和 observation 编号语义。
不通过新增伪 observation 记录指标，以免破坏完成证据引用或审批恢复。

- model_attempts：调用模型前先持久记录的尝试数，包括最终请求失败。
- model_responses/model_errors/model_unknown：已收到响应、明确失败、崩溃后无法确认结果的数量。
- tool_dispatch_attempts：进入 registry.call 前记录，包含被 registry 拒绝的请求，不冒充实际副作用次数。
- tool_outcomes：按 success/denied/approval_required/failed 等结果分类，未知单列；由已有结果记录支持。
- approval_stops/clarification_stops：新进入等待状态的次数，查看状态不增加计数；重复提示与独立人工决定不混淆。
- elapsed_active_seconds：执行器累计工作时长，不包含等待人工输入的离线间隔。
- verification_seconds：独立文件检查耗时，不重复计入执行耗时。
- case_wall_seconds：从案例启动至暂停或结束的本次墙钟时长，不宣称等于用户端到端耗时。

计数在原有检查点和每任务锁内累积；恢复不归零，状态查询与复查不增加模型调用数。
调用前登记并不证明 HTTP 已发送或副作用已发生；崩溃后的未决尝试保留 unknown，不猜测费用或重放动作。
旧任务没有 metrics 时标记 legacy_unavailable，不用猜出的零值伪装完整历史。

## 6. 模型用量与费用

保持 generate(...) -> str 兼容现有调用方，增加单次调用的结构化结果接口供执行器使用，
返回文本与已验证的用量元数据。不得用跨调用的全局 last_usage，避免失败后误复用上次用量。
不支持新接口的脚本/自定义模型仍能运行，其用量标记 unavailable。

Token 数只接受厂商明确返回的非负整数，不接受 bool、负数、非有限值或字符串猜测。
仅保留允许的输入/输出/总量及可解释的缓存分类，不保存原始响应、请求头或 Key。
每次用量区分 available/unavailable/invalid；聚合显示覆盖调用数及 complete/partial/unavailable，
部分用量不能呈现为完整总量。未知或失败请求不视为零消耗。

本阶段不内置实时价格，不自动查价。费用仅在用户显式提供对应模型、币种、
输入/输出每百万 Token 单价，且计费分类可完整解释时计算；它是 estimate，不是账单。
不支持的缓存/推理计费分类、模型不匹配或缺失用量导致费用 unavailable；已知部分可单列，
但不得冒充总费用。价格配置及有效日期随报告记录，不包含厂商凭据。
真实模型评估强制的是调用/步骤/时间预算，不提供未经验证的货币硬上限。

## 7. 接口与预算（拟新增）

以下是拟实现接口，不是当前可用命令：

```text
nexus executor evaluate --mode offline
nexus executor evaluate --mode live --max-calls 12
nexus executor evaluation-show EVALUATION_ID
nexus executor evaluation-review EVALUATION_ID --case CASE_ID --verdict passed --note TEXT
```

offline 为默认值，禁止初始化 LLM 厂商客户端，不读取个人 API 配置，不发起网络请求。
live 必须显式指定且提供 max-calls（1-100）；CLI 预先告知将向所选厂商发送合成案例资料。
未配置模型明确失败，不悄悄改用脚本模型，也不自动选别的厂商。
首次真实评估默认仅运行三个正常案例（每类一个）；显式选择其余内置案例才扩展范围。

每次套件最多 24 个案例，默认每案例 8 步、30 秒工作预算，套件默认 300 秒协作式预算。
每案例最多 16 次 registry dispatch，包含拒绝请求；验证读取另受 15.5a 预算约束。
真实模型每次请求前预留调用额度，重启不返还未知尝试；不自动重试厂商请求。
时间预算只阻止下一次工作，不能强行终止缺少超时能力的在途本地读取。
人类审批不自动通过；真实案例进入 waiting_approval/waiting_input 后记为需要介入并暂停该案例，
初版不做交互式套件恢复。离线故障脚本只操纵合成工具，不授权真实副作用。

参数超范围时提前拒绝，不自动截断至看起来合理的数字。未覆盖的案例保留预算停止原因。

## 8. 隔离、存储与隐私

评估工作区位于本地 NEXUS_HOME/evaluations/EVALUATION_ID，ID 使用新生成 UUID，
不得覆盖现有目录或接受任意输出路径。案例输入与检查条件是受版本控制的合成资料。
运行前在目录内构造独立 ExecutionStore 和合成工具配置，文件权限仅覆盖当前案例目录。
不继承日常自动化、MCP、个人目标/RAG/研究文档，也不复制个人主数据库。
只有 live 的模型凭据显式经现有 LLM 配置加载；不能持久化到评估目录或报告。

为系统生成的相对路径做目录边界检查，拒绝穿越、现有符号链接/目录联接与覆盖。
这沿用本地工具安全模型，不声称构成可抵抗恶意并发文件系统修改的 OS 沙箱。
中断不自动删除输出、不自动恢复副作用；评估状态记录 interrupted，已完成案例结果保留。

报告 schema_version=1，包含 evaluation_id、模式、案例集版本、案例状态、指标、
模型标识、预算和时间；JSON 为权威记录，Markdown 是便于阅读的投影。
报告每案例最多 4,000 字符摘要、50 条证据引用；整体输出上限 1 MiB，溢出显式报错。
原始提示词、完整模型响应、工具正文、API Key、审批令牌与私人路径不写入汇总报告。
模型摘要视为不可信文本，Markdown 转义，不渲染 HTML 或自动执行/访问链接。
程序不自动发布或提交评估结果；即便是合成数据也须人工查看后再分享。
人工评价只接受已存在的案例 ID，verdict 为 passed/partial/failed，note 限 1–4,000 字符；
追加带时间的记录，不改写原始机器结论。评价写入使用评估级互斥锁及原子替换，
避免并发覆盖。用户主动写入备注的私人信息仍属于本地明文，分享前需要自行检查。

| 文件 | 责任 |

| src/nexus/evaluation_cases.py（新） | 唯一权威案例源：版本化合成资料生成器、判据、开发/保留集标记与离线脚本模型 |

## 10. 验收与交付

1. offline 在没有 Key、没有网络的环境完整运行；任何厂商客户端构造均使测试失败。
2. 三类案例和八类故障使用同一执行器，不新增对应产品意图，不自动批准副作用。
3. 调用计数在响应失败、拒绝、取消与重启后保持准确或明确 unknown，验证不增加 LLM 次数。
4. 缺失/部分/非法用量、未配置价格、未知计费分类均不生成虚假的完整费用。
5. live 的调用上限在请求前生效；额度耗尽后不会调用下一案例的模型；测试用假 HTTP，不消耗付费 API。
6. 输出明确模式、适用分母与跳过原因；文件验收通过不自动变成人工语义评价通过。
7. 报告没有原始正文、凭据或审批令牌；真实评估只看合成数据和受限目录。
8. 现有审批、恢复、15.5a 复查、文字/语音入口及旧模型接口回归通过。

真实厂商小规模验收在代码通过后另行显式启动；没有真实运行结果就不报告真实模型成功率。
