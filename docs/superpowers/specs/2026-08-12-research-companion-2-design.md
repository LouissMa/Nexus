# Research Companion 2.0 Design

## Objective

Research Companion 2.0 turns the bounded Research Companion workspace into an evidence acquisition and analysis system. It can ingest local documents and repositories, acquire explicitly requested web pages, run explicitly approved bounded experiments, and coordinate a terminating research workflow that produces traceable findings instead of unsupported prose.

This phase does not claim autonomous science, unrestricted browser control, or an operating-system security sandbox.

## Scope

The release includes five connected capabilities:

1. Full-text ingestion for PDF, Markdown, and plain-text files with page/line-aware chunks.
2. HTTPS web-page acquisition with network safety checks, response limits, text extraction, and immutable acquisition metadata.
3. Repository indexing for an explicitly selected local root, with ignored directories, file limits, and line-aware chunks.
4. An explicitly approved experiment runner with executable allowlists, no shell, bounded working roots, timeout and output limits, and persisted results.
5. A deterministic multi-Agent research loop with shared budgets, a fixed maximum cycle count, evidence-grounded synthesis, criticism, and a terminal outcome.

OCR, JavaScript browser rendering, authentication crawling, arbitrary shell scripts, container orchestration, background autonomous loops, and write access outside the selected experiment workspace are deferred.

## Architecture

### Research corpus

`research_corpus.py` owns extraction, chunking, persisted corpus metadata, indexing, retrieval, citation validation, and removal. Corpus records remain inside the existing research project state while normalized chunks are stored in a project-scoped JSON index under the Nexus home directory. This avoids bloating `state.json` with full source text.

Each chunk has a stable content-derived ID and contains:

- project, document, and source IDs;
- source kind (`pdf`, `markdown`, `text`, `web`, or `repository`);
- page number or start/end line;
- bounded text and content hash;
- sparse vector generated by the local multilingual embedder.

Human-readable references use `document:<document-id>#page=<n>&chunk=<chunk-id>` for PDF and `document:<document-id>#lines=<start>-<end>&chunk=<chunk-id>` for text, web, and repository sources. A reference is valid only if its chunk still exists and the stored text hash matches.

### Acquisition boundaries

Local documents are read only after an explicit CLI/service call. Supported files are limited to 20 MiB. PDF extraction uses optional `pypdf`; a missing dependency produces an actionable error and leaves project state unchanged. Empty and encrypted PDFs fail explicitly.

Web acquisition accepts HTTPS only. It rejects credentials in URLs, localhost, private/link-local/loopback/reserved IP addresses, non-default ports, and oversized responses. Redirect targets are checked by the same policy. The stored record includes canonical URL, retrieval timestamp, response content type, content hash, title, and chunks. Query values are removed from audit-facing output.

Repository indexing resolves one explicit root, rejects files that escape it through symlinks, skips common generated/secret directories, accepts a bounded text-extension allowlist, and caps files, per-file bytes, and total corpus bytes. It never executes repository code while indexing.

### Experiment runner

The experiment runner receives an argument array, never a shell string. Execution requires `approved=True`, an executable from the configured allowlist, and a working directory under the configured experiment root. It uses `shell=False`, a minimal environment, a hard timeout, and capped stdout/stderr. Every attempt becomes a research experiment record with command metadata, exit status, duration, truncation flags, and a safety classification.

This is a restricted process runner, not a kernel or container sandbox. The UI and documentation must preserve that distinction.

### Research loop

`research_loop.py` coordinates fixed specialists:

- Planner identifies one bounded research question and next evidence gap.
- Retriever searches the project corpus and eligible long-term memory.
- Analyst builds findings using only returned references.
- Critic marks unsupported findings and identifies unresolved questions.
- Reflection chooses `complete`, `needs_evidence`, or `budget_exhausted`.

The loop has explicit limits for cycles, retrieved chunks, findings, optional LLM calls, and elapsed time. Network acquisition and experiment execution are never triggered implicitly. Optional LLM wording may reorganize text but must preserve the exact allowed references and uncertainty fields; invalid output is discarded.

Each run persists a sanitized trace containing step names, counts, statuses, terminal reason, and reference IDs, but not full document text, prompts, secrets, or command output.

## Product Surfaces

CLI commands extend `nexus research` with:

- `document-add`, `document-list`, `document-show`, `document-remove`, `document-reindex`, and `document-search`;
- `web-add` and `repo-index`;
- `experiment-run` with explicit approval;
- `run` for the bounded research loop.

The unified conversation supports read-only corpus status and search intents. Mutating ingestion and execution remain explicit CLI/service operations.

The Dashboard Research view adds bounded document/index/run summaries, source locations, and references. It never sends raw chunks, full command output, full filesystem paths, or prompts to the browser.

## Failure Model

Extraction, indexing, web acquisition, repository indexing, memory retrieval, optional LLM wording, and experiment execution fail independently. A failed acquisition does not create a partial document. A failed re-index preserves the last valid index. A research loop records degradation and can still produce an evidence-insufficient result from available local data.

## Testing And Release Criteria

The release requires:

- extraction and citation tests for PDF, Markdown, TXT, web, and repositories;
- path traversal, symlink, private-network, size, timeout, allowlist, output-cap, and approval tests;
- deterministic retrieval and stale-reference validation tests;
- terminating research-loop, budget, degradation, and unsupported-claim tests;
- CLI, conversation, Dashboard privacy, and responsive browser tests;
- synchronized English/Chinese README, architecture, roadmap, task checklist, and file inventory;
- full test suite, Ruff, format, diff, and added-line secret scans before pushing `main`.
