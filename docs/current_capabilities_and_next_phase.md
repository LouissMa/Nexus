# 当前能力与下一阶段

更新日期：2026-09-09。实现基线：`a4d5172`。

## 目标

Nexus 的长期目标是成为持续理解用户、完成真实任务的个人 AI 系统，由文字、
语音、网页和未来视觉、家庭设备、机器人接口共同使用。用户描述目标，系统选择
工具、安排步骤、观察结果、纠正行动并交付成果。找照片和打开应用是能力示例，
不是产品边界。此方向不意味着当前版本具有 AGI 能力。

## 已有能力

| 模块 | 已有实现 | 当前限制 |
| --- | --- | --- |
| LLM 配置 | OpenAI-compatible 接口、厂商与模型层级、本地配置、失败降级 | 接入模型不等于具备通用执行能力；外部服务需用户配置 |
| 长期记忆 | FastEmbed/API Embedding、Qdrant、混合检索、Re-index、重要性、压缩、隐私、遗忘 | 不等于完整的跨任务上下文或自动理解所有个人资料 |
| 生活管理 | 目标、打卡、每日计划、任务状态、阻碍、晚间复盘、Coach 模式 | 日程规划与电脑任务执行规划是不同层次 |
| 习惯与项目 | 习惯周期、连续打卡、里程碑、进度、关联目标和任务 | 尚不自动完成项目中的任意任务 |
| AI 建议 | 结合目标、状态、只读日历和 RAG 的建议、接受与忽略 | 主要是有结构的规则与可选 LLM 表述 |

| 多 Agent | Memory、Tool、Planner、Reflection、Coach 的有预算协作 | 专用编排，不是开放目标的通用自主协作 |
| 主动运行 | 早晨简报、晚间复盘、目标提醒、收件箱、Webhook、免打扰 | 需要显式启用并运行调度器；尚非完整事件驱动任务系统 |
| Dashboard | 今日任务、目标、习惯、项目、研究、建议、记忆、活动、设置 | 本地界面，尚非通用执行任务控制台 |

| 语音 2.0 | 本地 STT/TTS、VAD 连续轮流会话、退出短语、预算和静默退出 | 没有唤醒词、语音打断；审批会结束当前会话 |

## 下一阶段：Phase 15 通用任务执行核心

状态：规划已落地，运行时尚未实现。下一项开发任务是 15.1。

核心目标：面对没有专门编排过的请求，基于已注册工具动态执行，并以可检查的
结果判断完成。固定工具接口可以保留，但不能再为每种任务新增固定意图处理器。

| 里程碑 | 实现范围 | 验收标准 |
| --- | --- | --- |
| 15.1 工具契约与开源选型 | 统一输入/输出 Schema、权限、副作用、超时、幂等/重试声明；对比执行框架 | 能列出当前可用工具，拒绝非法参数，调用现有服务且不绕过权限；记录采用或不采用外部框架的依据 |
| 15.2 动态执行循环 | 单主 Agent 基于目标和观察选择下一步；调用、提问、完成、失败为明确动作 | 三类不同任务使用同一执行器，无需新增专用意图；工具失败后根据观察调整或停止 |
| 15.3 任务持久化与恢复 | 步骤、产物、待审批操作、运行状态、取消与恢复 | 重启后继续；审批绑定具体动作与参数，批准后不重做已完成写操作；不确定结果须先核验 |
| 15.4 上下文与接口 | 连接目标/RAG/研究能力；文字和语音共享任务；展示进度和结果 | 能解释当前在做什么、等待什么、产生了什么；不会将私密记忆无差别发送给外部工具 |
| 15.5 完成验证与评估 | 产物验证、预算、有限重试、重复动作检测和故障测试 | 文件真实存在且符合约定；证据不足或部分失败不报完整成功；有成功率、耗时、调用次数和可用的费用记录 |

实现策略：先单主执行 Agent，加受控工具适配器。现有专用 Agent 与研究循环作为
可调用能力逐步接入。任务存储复用项目的锁与事务机制；各工具继续通过原有权限层。
模型规划需要配置 LLM；无模型时明确说明动态执行不可用，现有本地命令仍可使用。

持久状态至少区分 queued、running、waiting_approval、waiting_input、paused、
succeeded、partial、failed、cancelled。执行前登记动作，执行后登记结果；崩溃发生在
副作用期间时，不能通过自动重试假设该动作未执行。费用上限只能在可获得使用量与
价格信息时强制执行，否则应显示不可用，并以调用/时间预算限流。

## 首批验收任务

1. 项目检查：读取指定授权仓库的文档和代码，生成带文件来源的未完成事项报告，
   验证输出文件。范围不确定时说明推断，不把任意 TODO 自动认定为项目需求。
2. 资料整理：在指定目录查找相关资料，读取支持的格式，生成带来源的索引，
   处理重复名称、不可读文件和结果截断。初期不删除或移动原文件。
3. 研究准备：结合已有研究资料和允许的检索能力，整理讨论提纲与证据缺口，
   生成可读报告。网络失败时保留已完成部分并说明缺失来源。

这些是验收样例，不是三个新的固定工作流。除基础回归外，需要使用未在提示词中
预编排的任务变体，覆盖工具不可用、用户取消、拒绝审批、重启、重复调用与虚假完成。

## 开源复用策略

在 15.1 中搜索并阅读公开仓库，按模块比较工具循环、审批恢复、任务持久化与
可观测性。OpenClaw 是候选参考，不是已经选定的依赖；电脑操作项目另行评估。
每个候选记录仓库 URL、检查日期与 commit、许可证、实际阅读的代码、维护状态、
Windows 兼容性、最小验证结果、接入代价。优先考虑清晰的库/API/MCP 边界，避免
同时引入两套任务状态和权限系统。没有实际调研或验证时不写“已完成选型”。

## 后续顺序

通用执行核心 -> 完整文件/浏览器/电脑操作 -> 连续个人与任务上下文 -> 事件驱动
主动助手 -> 更自然语音与视觉 -> 家庭身份/设备 -> 仿真与受控机器人集成。

这些是演进顺序，不是一次性承诺。后续每阶段继续使用真实任务成功率、人工介入、
恢复能力、耗时与费用验收。当前阶段不会顺带宣称完成唤醒词、桌面视觉、家庭控制
或机器人运动控制。
